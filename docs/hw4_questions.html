MaxDiff Analysis of MSBA Class Preferences

Counts, maximum likelihood, and Bayesian estimation of the MNL model

Author

Kristin Yang

Published

May 28, 2026

Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring preferences through trade-offs. Instead of asking students to rate every class from 1 to 10, the survey shows a small set of classes and asks for the most-preferred and least-preferred option. That is useful because people are usually better at making comparisons than at using rating scales consistently.

Here the items are the core MSBA classes at UCSD Rady. I estimate class preferences three ways. First, I use a simple counts score: the share of times a class was picked best minus the share of times it was picked worst. Second, I estimate a multinomial logit (MNL) model by maximum likelihood. Third, I estimate the same MNL model with a Bayesian random-walk Metropolis sampler.

My expectation is that all three methods should mostly agree on the ranking. The main difference is interpretation: counts are descriptive, MLE gives model-based point estimates and standard errors, and the Bayesian version makes it easy to describe uncertainty for quantities such as shares of preference.

The Data

The raw file contains one row for each item shown on a survey screen. The key columns are respondent ID, task number, item position, item number, and response. A response of 1 means the item was chosen as best, -1 means chosen as worst, and 0 means it was shown but not selected.

One data-cleaning decision is worth making explicit. The raw file contains 3910 rows. It includes 595 two-row tasks with an unlabeled Item == 11; those rows do not match the 10-class label file or the four-item MaxDiff structure. I treat those as a separate survey block and analyze only the valid MaxDiff tasks: four rows, one best pick, one worst pick, and two neutral rows.

Counts Analysis

The counts analysis is the quickest way to summarize a MaxDiff survey. For each class, I calculate the percentage of times it was picked best and the percentage of times it was picked worst, always using the number of times the class was shown as the denominator:

\[ \text{score}_j = \%\text{best}_j - \%\text{worst}_j. \]

A positive score means the class was more often chosen as best than worst. A negative score means the reverse. I also bootstrap respondents 1,000 times to get a rough confidence interval for each score.

Code 
counts_summary <- maxdiff |>
  group_by(Item) |>
  summarize(
    times_shown = n(),
    times_best = sum(Response == 1),
    times_worst = sum(Response == -1),
    pct_best = times_best / times_shown,
    pct_worst = times_worst / times_shown,
    score = pct_best - pct_worst,
    .groups = "drop"
  ) |>
  left_join(item_labels, by = "Item")

respondent_ids <- unique(maxdiff$`Record ID`)

From MaxDiff Data to MNL Choices

The MNL model turns each task into probabilities. If a screen shows classes \(\{a,b,c,d\}\), the probability that class \(b\) is chosen best is

\[ P(\text{best}=b) = \frac{\exp(\beta_b)} {\exp(\beta_a)+\exp(\beta_b)+\exp(\beta_c)+\exp(\beta_d)}. \]

The worst pick can be modeled as a second choice from the remaining three items, but with utilities flipped. If \(b\) was already selected as best, the probability that class \(c\) is chosen worst is

\[ P(\text{worst}=c \mid \text{best}=b) = \frac{\exp(-\beta_c)} {\sum_{j \in \{a,c,d\}}\exp(-\beta_j)}. \]

Only differences in utility are identified. Adding the same constant to every \(\beta\) leaves all soft-max probabilities unchanged. I use item 1, AI Math & Programming, as the reference class and set \(\beta_1=0\).

Code 
choice_tasks <- maxdiff |>
  arrange(`Record ID`, Task, Position) |>
  group_by(`Record ID`, Task) |>
  summarize(
    shown_items = list(Item),
    best_item = Item[Response == 1],
    worst_item = Item[Response == -1],
    .groups = "drop"
  )

shown_matrix <- do.call(rbind, choice_tasks$shown_items)
best_item <- choice_tasks$best_item
worst_item <- choice_tasks$worst_item

MNL via Maximum Likelihood

For one task, the log-likelihood is the log probability of the observed best pick plus the log probability of the observed worst pick:

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[ \beta_{j_b^*} - \log \sum_{j \in \text{shown}}\exp(\beta_j) - \beta_{j_w^*} - \log \sum_{j \in \text{shown}\setminus\{j_b^*\}}\exp(-\beta_j) \right]. \]

The code below estimates the nine free coefficients with optim(). I use a small log-sum-exp helper so the denominator is computed safely on the log scale.

Code 
log_sum_exp <- function(x) {
  m <- max(x)
  m + log(sum(exp(x - m)))
}

ll <- function(theta) {
  beta <- c(0, theta)
  total <- 0

  for (i in seq_len(nrow(shown_matrix))) {
    shown <- shown_matrix[i, ]

    total <- total +
      beta[best_item[i]] -
      log_sum_exp(beta[shown])

    remaining <- shown[shown != best_item[i]]

    total <- total +
      (-beta[worst_item[i]]) -
      log_sum_exp(-beta[remaining])
  }

  total
}

mle_out <- optim(
  par = rep(0, total_items - 1),
  fn = ll,
  method = "BFGS",
  hessian = TRUE,
  control = list(fnscale = -1, maxit = 1000)
)

beta_mle <- c(0, mle_out$par)
vcov_mle <- solve(-mle_out$hessian)
se_mle <- c(NA_real_, sqrt(diag(vcov_mle)))
mle_share <- exp(beta_mle) / sum(exp(beta_mle))

mle_summary <- data.frame(
  Item = seq_len(total_items),
  beta_mle = beta_mle,
  se_mle = se_mle,
  mle_share = mle_share
) |>
  left_join(item_labels, by = "Item") |>
  mutate(mle_rank = min_rank(desc(mle_share))) |>
  arrange(mle_rank)

The optimizer converged with a log-likelihood of -1 572.731. The shares of preference are easier to interpret than raw utility coefficients. They answer a hypothetical question: if all 10 classes were shown together, what share of choices would each class receive under the estimated model?

MNL via Bayesian Estimation

The Bayesian version uses the same likelihood but adds a weakly informative prior:

\[ \boldsymbol{\beta} \sim N(\boldsymbol{0}, 10I). \]

I use a random-walk Metropolis sampler. The proposal is centered at the current parameter vector, and the chain accepts or rejects the proposal based on the posterior density ratio.

Code 
log_posterior <- function(theta) {
  ll(theta) + sum(dnorm(theta, mean = 0, sd = sqrt(10), log = TRUE))
}

mh_sampler <- function(theta0, n_iter, step) {
  K <- length(theta0)
  draws <- matrix(NA_real_, nrow = n_iter, ncol = K)
  theta <- theta0
  current_lp <- log_posterior(theta)
  accept <- 0

  for (iter in seq_len(n_iter)) {
    theta_star <- theta + rnorm(K, mean = 0, sd = step)
    proposal_lp <- log_posterior(theta_star)

    if (is.finite(proposal_lp) &&
        log(runif(1)) < proposal_lp - current_lp) {
      theta <- theta_star
      current_lp <- proposal_lp
      accept <- accept + 1
    }

    draws[iter, ] <- theta
  }

  list(draws = draws, accept_rate = accept / n_iter)
}

tuning_steps <- c(0.05, 0.08, 0.10, 0.12)
tuning_results <- data.frame(
  step = tuning_steps,
  accept_rate = NA_real_
)

for (i in seq_along(tuning_steps)) {
  set.seed(455)
  trial <- mh_sampler(mle_out$par, n_iter = 3000, step = tuning_steps[i])
  tuning_results$accept_rate[i] <- trial$accept_rate
}

set.seed(455)
n_iter <- 20000
burn_in <- n_iter * 0.25

The three methods agree almost perfectly in this dataset. The top class is Marketing Analytics no matter how I estimate preferences, and the bottom class is Analytics Consulting. The middle classes are closer together, especially Capstone and SQL, so this is where I would expect rankings to be less stable in another sample.

The MNL model adds structure beyond the counts analysis. It models each best and worst decision as a probabilistic choice from the shown set, so every item shown contributes information. Bayesian MNL adds a convenient way to carry uncertainty through nonlinear quantities such as shares of preference.

Discussion

The substantive takeaway is that students in this survey strongly prefer Marketing Analytics. Business Analytics and Customer Analytics are also attractive, while Analytics Consulting, M/F/O, and AI Math & Programming are less preferred in this sample. The size of the Marketing Analytics lead is the most striking result: it is not just first by a little; it is first across every method by a large margin.

For a quick dashboard, I would use the counts score because it is simple and easy to explain. For a more rigorous point estimate, I would use the MLE MNL model because it has a clear likelihood and classical standard errors. If I wanted uncertainty for simulations or derived outcomes, I would use the Bayesian MNL approach because posterior draws can be pushed through any downstream calculation.

The caveat is that these are preferences from a self-selected group of MSBA students. The results may reflect current instructors, prior coursework, timing in the program, or the particular students who answered the survey. If I had more time, I would estimate a hierarchical model that allows preferences to vary by student and compare whether different segments of students rank the classes differently.
